# 开发文档

> 面向开发者：如何在本项目上继续开发、扩充题库

## 1. 本地开发

```bash
npm install
npm run dev       # 开发（热更新）
npm run build     # 类型检查 + 生产构建
npm run preview   # 本地预览构建产物
```

## 2. 领域模型速查（src/data/types.ts）

```ts
interface Question {
  id: string            // '{moduleId}-{三位序号}'，如 'os-007'，全局唯一
  moduleId: string      // 模块 id，见下表
  chapter?: string      // 章节名（与知识点章节、练习筛选用）
  stem: string          // 题干，Markdown
  options: string[]     // 恰好 4 项，不含 'A.' 前缀
  answer: number        // 0~3
  explanation: string   // 解析，Markdown
  difficulty: 1 | 2 | 3
  hot?: boolean         // 高频标记
}

interface Chapter {
  id: string            // '{moduleId}-c{n}'
  title: string
  content: string       // Markdown 精讲
  hot?: 1 | 2 | 3       // 3 必考 / 2 常考 / 1 了解
}

interface CaseQuestion { // 下午案例大题
  id: string
  category: 'dfd' | 'db' | 'uml' | 'algo' | 'oop'
  title: string
  material: string      // 背景材料 Markdown（图用文字化清单描述）
  subQuestions: { id: string; stem: string; points: number; referenceAnswer: string; scoringPoints?: string[] }[]
  techniques?: string   // 解题套路 Markdown
}
```

## 4. 如何新增题目

**方式一：直接编辑数据文件（推荐）**

1. 打开 `src/data/questions/{moduleId}.ts`（如 `os.ts`）；
2. 在数组末尾按既有格式追加题目对象，id 接续现有最大序号；
3. 保存后开发服务器自动热更新，无需注册——`questions/index.ts` 的聚合与组卷配额自动生效。

**方式二：批量导入脚本（题量大时）**

写一个临时脚本把你的题源（Excel/JSON/文本）转换为 `Question[]` 并写入对应 ts 文件。注意保持字段完整、id 全局唯一。

### 内容编写规范

- 字符串用单引号；换行写 `\n`；**不要使用反引号字符**（Markdown 代码块用 4 空格缩进，强调用 `**星号**`）；
- `answer` 必须与 `explanation` 一致；解析应说明正确项依据并点出易错点；
- 计算类题目（子网划分、PV 初值、页表变换、挣值等）提交前必须人工验算；
- 高频题（约占 1/3）打 `hot: true`；
- 英语完形题：每题 stem 中包含完整短文（空位形如 `__(71)__`），多题共享同一短文。

## 5. 如何新增知识点章节

编辑 `src/data/knowledge/{moduleId}.ts`，在 `chapters` 数组追加：

```ts
{
  id: 'os-c5',            // 接续编号
  title: '新章节标题',
  hot: 2,
  content: '## 小节\n\n……',
}
```

建议结构：核心概念 → 考点清单（表格）→ 易混淆对比 → 记忆口诀。`chapter.title` 与选择题的 `chapter` 字段对应得越准，「章节练习」的按章筛选体验越好。

## 6. 如何新增案例大题

编辑 `src/data/cases.ts` 追加 `CaseQuestion`：

- `category` 决定它在案例分析专项与模考下午卷中的归类；
- **模考下午卷自动取每类第一道题**（oop 类取 `oop1`=C++ / `oop2`=Java），因此 id 需遵守该约定，或修改 `MockExam.tsx` 中的取题逻辑；
- 每道大题小题分值合计建议 15 分，贴近真题；
- 图（DFD/ER/类图）以「文字化清单」表达，参考文件中已有写法。

## 7. 部署（自建服务器）

线上地址：**https://jzhm.fun/ruankao/**（与 AIword 等项目同域，nginx 按路径前缀分发）。

### 部署架构

```
浏览器 ──HTTPS──▶ nginx (82.156.224.145, jzhm.fun)
                  └─ location ^~ /ruankao/ ──▶ alias /www/wwwroot/ruankao/（纯静态 dist）
                        try_files $uri $uri/ /ruankao/index.html   ← SPA 深路径刷新兜底
```

- 服务器目录：`/www/wwwroot/ruankao/`；nginx 配置：`/etc/nginx/conf.d/00-default.conf`（改动前先按 `.bak.时间戳` 备份）
- 子路径部署的两个关键配置：`vite.config.ts` 的 `base: '/ruankao/'` 与 `main.tsx` 的 `<BrowserRouter basename={import.meta.env.BASE_URL}>`（缺一不可：前者修静态资源引用，后者修路由匹配）


服务器端旧版本保留在 `/www/wwwroot/ruankao.old`。回滚：

## 8. 组卷配额调整

近年真题各模块上午题量变化时，修改 `src/data/questions/index.ts` 的 `MOCK_QUOTAS`（合计应为 75）。配额只是抽题上限，题库不足时自动从其他模块补齐。

## 9. 状态与持久化

- `src/store/useAppStore.ts`：设置、作答记录（上限 5000）、错题本、收藏、章节掌握、模考历史与进行中的模考；持久化键 `rk-designer-store`。
- `src/store/useCaseDraft.ts`：案例分析专项草稿；持久化键 `rk-case-draft`。
- **修改 store 字段时的兼容性**：persist 恢复时旧数据与新字段按 zustand 默认策略合并（缺失字段取初始值）。若做破坏性变更，建议在 persist 配置中加 `version` + `migrate`，或引导用户重新导入导出的 JSON。

## 10. 模考计时规则实现要点

见《技术架构文档》5.2 节。关键点：**所有剩余时间均由 `activeMock.startTime` 派生**，勿引入可暂停的累计计时，否则刷新恢复语义会被破坏。

## 11. 编码与提交约定

- 组件用函数组件 + Hooks；页面放 `pages/`，可复用 UI 放 `components/`；
- 样式统一 Tailwind 工具类，主题色使用 `primary` 色板，避免内联硬编码色值；
- 中文文案直接写在 JSX 中，无需 i18n；
- 提交信息建议格式：`feat: xxx` / `fix: xxx` / `docs: xxx` / `content: 新增xx模块nn题`。
