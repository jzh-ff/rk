# 技术架构文档

> 项目：软考软件设计师学习与练习网站
> 更新日期：2026-09-07

## 1. 架构总览

本项目为**纯前端单页应用（SPA）**，无后端服务与数据库：

```
浏览器
 ├── React SPA（Vite 构建）
 │    ├── 页面层（react-router-dom 路由）
 │    ├── 状态层（zustand + persist → localStorage）
 │    └── 数据层（TS 数据文件：题库 / 知识点 / 案例题）
 └── localStorage（学习进度持久化）
```

选型理由：个人备考工具，单机使用即可满足需求；纯静态产物可部署到任意静态托管（GitHub Pages / Vercel / Nginx）；零运维成本。

## 2. 技术栈

| 层 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |

| 路由 | react-router-dom | 6 | 声明式路由 + 动态路由（知识点模块/章节） |

| AI | OpenAI 兼容 chat/completions | — | 浏览器直连大模型 API（智谱 GLM / DeepSeek / Ollama 等），见 services/ai.ts |

## 4. 领域模型（src/data/types.ts）

```ts
ModuleConfig   模块配置（id/名称/简介/组卷配额 examCount）
Question       选择题（id、moduleId、chapter、stem、options[4]、answer、explanation、difficulty、hot）
CaseQuestion   案例大题（category: dfd|db|uml|algo|oop、material、subQuestions、techniques）
CaseSubQuestion 案例小题（stem、points、referenceAnswer、scoringPoints）
Chapter        知识点章节（title、content、hot: 1|2|3）
```

命名约定：模块 id 为两字母缩写（co/os/db/nw/sec/se/oo/ds/pl/math/law/en）；题目 id 为 `{moduleId}-{三位序号}`（如 `se-013`），全局唯一，是错题本/收藏/作答记录的关联主键。

## 5. 核心机制设计

### 5.1 智能组卷（buildMockPaper）

`questions/index.ts` 中的 `MOCK_QUOTAS` 记录各模块在近年真题上午卷中的典型题量（如 oo:11、se:9、ds:9……合计 75）。组卷时按配额从各模块题库**随机抽取**再全卷打乱；题库不足时从剩余题目补齐。将来扩充题库无需改代码，配额自动生效。

### 5.2 连考计时（真实机考规则）

模考状态 `ActiveMock` 持久化到 localStorage，**计时锚点为 `startTime`**，刷新页面后重算剩余时间，天然防篡改、可恢复：

- 总时长 240 分钟，超时强制收卷（useEffect 监听自动交卷）；
- 上午卷 0~90 分钟内禁止交卷（按钮禁用 + 提示），120 分钟自动强制交卷；
- 上午交卷即冻结 `morningDurationMin`，剩余时间自然顺延至下午环节；
- 下午环节倒计时与上午共用同一起点，总时长耗尽自动 `finishMock`。

### 5.3 作答记录与错题本

- 任何模式的作答（练习/错题重练/模考）统一写入 `records`（上限 5000 条，新的在前），正确率统计跨模块复用；
- 答错自动写入 `wrongBook`（记录错误次数与最后错选）；错题重练答对自动移出；
- 模考交卷在 `submitMorning` 中一次性判分并批量写入 records（mode: 'mock'）。

### 5.4 AI 能力（src/services/ai.ts）

浏览器**直连 OpenAI 兼容接口**（`POST {baseUrl}/chat/completions`），无自建后端：

- 配置（baseUrl / model / apiKey）持久化在 store `aiConfig`，Key 只存本机 localStorage；
- 内置预设：智谱 GLM、DeepSeek、Ollama 本地（`OLLAMA_ORIGINS=*` 解决 CORS）；
- 四个能力入口：全局答疑抽屉（AiAssistant）、题目深度讲解（QuestionCard）、智能出题（AiQuiz 页，严格 JSON 数组输出 + `extractJsonArray` 容错解析 + 字段校验）、案例 AI 阅卷（CaseQuestionCard）；
- **AI 题入库机制**：用户认可的 AI 生成题存入 `store.aiQuestions`（上限 1000），id 约定 `{moduleId}-ai-{时间戳}-{序号}`——模块前缀保持标准格式，因此错题本/收藏/统计（按 id 前缀归属模块）对 AI 题天然生效；`findQuestion(id, aiQuestions)` 统一合并查找静态题库与 AI 题；章节练习自动并入对应模块。

### 5.5 数据持久化与迁移

- zustand persist 两个存储键：`rk-designer-store`（全局）、`rk-case-draft`（案例草稿）；
- 设置页支持导出/导入 JSON 全量备份，字段与 store 状态一一对应。

## 6. 页面路由

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | Dashboard | 倒计时与统计 |
| `/knowledge`、`/knowledge/:moduleId`、`/knowledge/:moduleId/:chapterId` | Knowledge | 三级下钻 |
| `/practice?module=&chapter=` | Practice | 查询参数驱动 |
| `/mock` | MockExam | 内部状态机：入口→上午→(选语言)→下午→完成 |
| `/case` | CaseStudy | 按题型分类 |
| `/wrong` | WrongBook | 列表/重练 |
| `/settings` | Settings | 备份恢复 |

## 7. 部署

`npm run build` 产出 `dist/` 静态文件：

- **本地**：`npm run preview` 直接预览；
- **静态托管**：GitHub Pages / Vercel / Netlify 一键部署；若部署到子路径，需在 `vite.config.ts` 设置 `base`；
- **注意**：SPA 使用 BrowserRouter，部署到 Nginx 等需配置所有路径回退到 `index.html`。
